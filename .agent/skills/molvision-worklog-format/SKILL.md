# MolVision 输出文稿固定格式

三个模板覆盖全部输出场景。**字段不可缺；写实际实测数字，不写「应该/大概」。**

## 模板一：worklog 段（每 agent 每任务一段）

```markdown
---
Task ID: <轮次-字母，如 r105-a>
Agent: <agent 名>
Task: <任务一句话>

Work Log:
- 【读基】<读了什么、多少行、基线数字>
- 【改动】<每文件每改动点，含实态数字>
- 【验证】<门禁实跑结果数字>

Stage Summary:
- 交付：<...>
- 验证：<门禁结果数字>
- 与任务书偏差（如有）：<...>
- 遗留（供下轮参考）：<...>
```

Work Log 三条目对应开工三动作（读了什么/改了什么/验了什么），多条可拆子弹行；Stage
Summary 是交接面（交付/验证/偏差/遗留四字段——偏差与遗留可为「无」，字段本身不缺）。

## 模板二：子代理任务书

```markdown
Task ID: <轮次-字母，如 r105-b>
Agent: <agent 名/类型>
任务：<任务一句话 + 背景依据（上轮建议编号）>

## 读基（开工前必读）
- <文件 + 行数范围>（例：worklog.md 尾部 ~200 行；scripts/xxx 尾部）
- <基线确认项>（例：git log -5 + status；guards 实跑记数）

## 任务
1. <具体交付点（含关键实现约束）>
2. ...

## 交付
- <文件清单（精确路径）>
- <守卫新增条数与插入点说明>

## 红线
- 不 git commit / 不 push（主代理统一）
- 不跑 E2E（主代理统一）；不碰 <范围外文件，如 src/>
- Bash 命令字符串绝不出现 kill/TERM/KILL 等网关过滤字样

## 收尾
- 向 worklog.md 追加 <Task ID> 段（用模板一；以 --- 行开头，追加不覆盖）
```

## 模板三：测试报告

```markdown
### <场景名>
- 场景：<测什么、为什么测（上轮遗留/回归面）>
- 步骤：<操作序列（命令/eval 摘要）>
- 断言：<预期 vs 实测数字（例：hbond 2202 条 / draw calls 39 / guards 593/593）>
- 结论：PASS / FAIL
- 证据：<截图路径 或 控制台输出摘要>
```

## 附加纪律

- **每段 MUST 以 `---` 行开头；追加不覆盖**——worklog 是只增账本，覆盖即销毁他人记录
- **写实际实测数字**，不写「应该/大概」（guards 593/593、smoke 6/6、漂移 0.02% 这种）
- 新坑单独成条入档（触发条件 + 现象 + 解法）——下轮 agent 靠它避坑
- 与任务书偏差如实列出，不静默吸收；遗留项写给下轮（「遗留（供下轮参考）」字段）
